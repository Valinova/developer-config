# Lenses

Standing units. Drop one only when recon shows the surface does not exist, and
say so in the coverage section. Add repo-specific units from recon.

## Where the boundary lives

The lenses ask the same questions on every stack; what changes is where the
first authorization decision is made, and so what "every callable endpoint"
means. Recon settles this before units are cut.

| Stack shape | The boundary to classify | What bypasses it |
|---|---|---|
| Function backend (each client call is a server function) | Every exported function, by the wrapper it is built with | A wrapper that only establishes identity; internal functions reachable through a public one |
| Database exposed to the client (Postgres behind an auto-generated API with row-level security) | Every table, view, function and storage bucket in the exposed schema, by its policy per operation; the public client key is the attacker's credential | A table with row security off; a policy that trusts a client-set column or claim; a view or definer-rights function that runs as its owner; any server code holding the service key, where the code is the only check |
| Own API over a document or SQL store (services on a cloud account) | Every route and handler, by its authorizer, and the tenant filter in every query | A handler behind no authorizer; a filter taken from the request; then the account itself: network reachability of the store, role permissions, bucket policies, signed-URL scope |

## The units

| Lens | The question | Typical miss |
|---|---|---|
| **Signed-out surface and identity** | What can a caller with no session read, write, or trigger? How is a principal resolved from a token: by which claim, bound to which issuer and audience, with what verification of that claim? | Public provisioning calls; identity by email with no verified-email requirement; a deactivated or removed principal that still resolves. |
| **Callable-endpoint classification** | For every callable endpoint, what is the first authorization decision? Classify each: A none, B principal resolved but nothing decided, C internal-only (the guard verifiably rejects low-trust principals), D low-trust by design with a scope check. The complete table is the coverage claim. | A wrapper that requires only "some identity"; a helper whose name promises more than it checks. |
| **Isolation on the designed low-trust surface** | For every D: is the tenant taken from the principal and never from arguments? Is the record bound to the caller before anything is returned or written? Do nested reads, lists, exports, and URLs apply the same scope? Is the return an explicit field grant or an internal row with fields removed? | Enriched reads; pre-authorization existence oracles; fields the client never renders. |
| **Injection and code execution** | Where does a low-trust value become part of a query, a command, a path, a template, markup, or a deserialized object? Follow it to the sink and name what makes it data there: a bound parameter, an allowlist, an escaper. | A query assembled from strings or from a client-supplied filter object; an operator object where a string was expected; a raw HTML sink; a file path joined from input. |
| **Machine and delegated credentials** | API keys, OAuth, service or bridge tokens, chat-platform identities: how each is minted, stored, verified, bound (owner, scope, audience), and revoked, and which input chooses the identity it asserts. | No audience binding; a chat profile email standing in for an account; revocation that misses one credential type. |
| **Model and agent delegation** | Where a model can act: who the tools run as, whether each write re-checks the requester at the app's own owner, whether a confirmation binds the exact arguments, requester, and expiry, and what attacker-writable content reaches a model that can act or exfiltrate without a human click. | An actor chosen by arguments; writes with no confirmation; a model-chosen fetch target; auto-loaded links or images. |
| **Files and bytes** | Upload routes, admission of stored-file references (never by mere existence), URL issuance, preview and same-origin rendering, parsers, exports, outbound fetches with a controllable host, and markup in outbound mail. | A file reference accepted because it exists; a delete with no reference check. |
| **Low-trust values reaching money or authority** | Which amounts, taxes, currencies, quantities, and dates does a low-trust principal supply, what bounds each, and can an unbounded one reach an approved or payable state with no person on the trusted side looking at it? | A ceiling that covers one figure and not the one that is paid; client-supplied text standing in for a document the server never read. |
| **Outbound channels** | What leaves toward low-trust recipients (mail, documents, webhooks, chat), built from which fields, sent to a recipient list computed how? What comes back in on the same channel, and is the sender's current standing checked? | An internal row rendered into a message; a reply path that outlives the recipient's access. |
| **Insider separation of duties and money** | Can one person request and approve, do the work and review it, change a record after approval while keeping the approval, grant themselves a role, or move money alone? Under impersonation or simulation, which writes are allowed and is the real actor recorded durably? | An override role that can fill every slot; an audit trail that is cleared when impersonation ends; a review with no author check. |
| **Lifecycle** | Soft-deleted and restored records, revoked or downgraded principals holding live sessions, keys, pending approvals, or queued work; compatibility shims that widen access mid-migration. | Authority frozen at assignment and never re-checked, with no documented remedy. |
| **Availability: spend and exhaustion** | From the low-trust principals: every path to a paid call (model, speech, search, mail), unbounded writes and stored files, work done before authentication, shared documents a low-trust write contends on, and reads whose cost is not bounded by the caller's own data. Require an input-to-cost path, a missing effective bound, and shared impact; never stress anything. | A ceiling counted per item when the principal can mint items; a ceiling on one entry path that its sibling skips; upstream quota shared with real sign-ins. |
| **Availability: poison data, destruction, lockout** | A low-trust value the write path accepts and a shared reader rejects, so one row fails a list, dashboard, or batch for everyone; a batch with no per-item isolation; anything a low-trust principal can delete or reset that others rely on, and whether it is recoverable; state they can flip for someone else. | A fail-closed assertion reachable from tenant data; a hard delete of a file other rows reference. |
| **Exposed stack and deployed surface** (the orchestrator) | Secrets in the tree or its history; CI triggers, token permissions, and action pinning; install-script trust; security headers; advisories against internet-facing packages; whether authorization lives at the resource or only in middleware. Then the owner checks source cannot answer: non-production environments holding production data or live integrations, preview deployments, sign-up policy, provider-side verification and quotas. | Auth that exists only in a proxy layer; a development environment that can move real money. |
