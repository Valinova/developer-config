# Filing issues

Read before filing an issue or running an audit that files; `principles.md` §8 points here.

- **An issue needs an observed, reachable, or deletes bar, checked before filing and never written into the issue.** Observed means a user said it, Sentry fired, or a data count shows wrong output today. Reachable means a reasonable chance, even as a prod edge case, of wrong money, data, permissions, or a lost request, judged from a real read of the path, not a skim; name the entry point and wrong outcome; no repro is needed, and a failed one does not close a gap the code shows. Depth follows apparent risk: what looks plausibly bad gets a deeper look (trace the path, query the data) before filing; what looks high-risk is investigated immediately, even mid-PR, to fix it or set its priority. Deletes names what goes. A rule the code does not yet meet, a smarter lint, a tighter type, a test rewrite, or low-likelihood "could happen if…" is never filed: it stays in the audit report, or becomes a `simplified:` marker at its one site. An issue I explicitly ask for passes as directed; an agent never claims that on its own initiative. The body is for a human reader: visual and concise, a sketch of the flow or architecture it touches and the North Star it moves toward, then blast radius in one sentence, what must be analyzed or built, pointers verified against a named SHA, and done-when lines. No pros-and-cons surveys or restated rationale. The bucket is a label (`priority:high` wrong output or lost request today, `priority:medium` reachable and contained, `needs-decision`; there is no `someday`). An audit run files only what passes and reports how many findings it did not file. (why: rationale.md#issue-bar)
- **Fold by root, not by symptom.** Before filing, identify the root cause and its owner (§5). One issue per root; each copy of its rule and each symptom the fix settles is a checkable "done when" line (`- [ ] …`), ticked when the slice that proves it lands; code that only looks alike is not a line. A symptom of an open root is a line there, never its own issue. Clear-cut cleanup is never filed: §3 says where it ships.
